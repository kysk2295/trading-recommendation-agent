# 전문 트레이딩 에이전트와 Loop Engineering 설계

**상태:** 사용자 승인

**제품 목표:** Day, Swing, Systematic Quant 에이전트가 가격·거래량·수급·뉴스·공시·시장 체제를 연구하고, 진입가·손절가·목표가가 포함된 추천을 실시간으로 제공한다. 승인된 US Day 추천은 Alpaca Paper에서 자동 실행하며, 판단·체결·성과·연구·학습 결과를 대시보드에 공개한다.

## 1. 설계 결정

이 설계는 다음 결정을 고정한다.

- 사용자에게 보이는 전문 에이전트는 `Day Trading`, `Swing Trading`, `Systematic Quant` 세 개다.
- Opportunity Scanner, Market Context, News & Filing Search, Critic, Risk Kernel, Paper Executor는 에이전트가 아니라 공통 서비스다.
- 기존의 방법론별 고정 연구 정체성은 `agent`가 아니라 `research lane` 또는 `methodology owner`로 취급한다.
- 에이전트는 지속적인 `ResearchTask`와 다단계 도구 루프를 갖는다.
- US Day Agent의 자연 시장 수직 경로를 먼저 완성한다. Swing, Quant, 한국 Day Shadow는 그 뒤에 연결한다.
- 신규 가설과 새 Agent 버전은 같은 날 Paper 주문 자격을 얻지 않는다. 미래 Shadow와 승격 게이트를 통과해야 한다.
- 인지적 자율성은 넓게 허용하지만 데이터 적격성, 위험, 주문, 감사, 승격 규칙은 결정론적 커널이 소유한다.
- 실제 실행은 정확히 `https://paper-api.alpaca.markets`만 허용한다. 한국 시장과 다른 공급자는 읽기 및 Shadow 전용이다.

## 2. 기존 방향과의 관계

이 설계는 기존 Day Trading의 Discovery, Future Shadow, Promotion/Execution 분리를 유지한다. 다만 `bounded prompt + cycle당 primary action 하나면 충분하다`는 해석은 폐기한다.

에이전트는 한 번의 구조화 응답을 만드는 함수가 아니다. 하나의 ResearchTask 안에서 제한된 예산으로 자료를 조사하고, 도구 결과를 관찰하고, 가설과 코드를 수정하고, 다음 행동을 선택한다. 구조화 JSON은 연구의 시작점이 아니라 아티팩트 제출 경계에서만 사용한다.

## 3. 제품 에이전트

### 3.1 Day Trading Agent

Day Agent는 테마·촉매·수급을 읽는 인간형 장중 트레이더다. 단순 기술지표 신호 생성기가 아니다.

주요 책임:

- 장전 시장 체제, 뉴스, 공시, 실적, 갭, 거래대금 지도 작성
- 여러 종목의 동시 움직임과 공통 촉매로 테마 탐지
- 테마 상태를 `발견 → 확산 → 주도 → 과열 → 약화 → 종료`로 추적
- 뉴스 직접성, 최초 반응, 거래대금 지속성, 상대강도, 가격 발견 주도 여부로 대장주 선정
- 상대 거래량, 거래대금 변화, 스프레드, 호가·체결, VWAP 반응, 돌파 후 매물 소화 등 관측 가능한 수급 해석
- 진입 조건, 손절가, 목표가, 무효화 조건이 포함된 Trade Thesis 생성
- 추천 이후 테마 약화, 대장주 교체, 뉴스 변경, 수급 이탈을 재평가
- 정규장 안에서 US Alpaca Paper 주문 상태를 추적하고 당일 포지션을 청산

직접 관측할 수 없는 수급 주장은 사실처럼 기록하지 않고 `inferred`로 표시한다.

### 3.2 Swing Trading Agent

Swing Agent는 수일에서 수주 동안 유지되는 기업·산업·테마 논리를 연구한다.

- 실적, 가이던스, 기업 공시, 산업 변화, 기관·외국인 수급, 중기 가격 구조 분석
- 진입, 손절, 목표, 투자 논리 무효화 조건 생성
- 보유 중 발생한 새로운 공시와 뉴스로 투자 논리 재평가
- 여러 세션에 걸친 촉매 지속성, 체제 적합성, 논리 유지 품질 평가

Swing은 Day 전략의 보유 기간을 늘린 변형이 아니다. 독립된 기억, 연구 과제, Playbook, 평가 기준을 가진다.

### 3.3 Systematic Quant Agent

Quant Agent는 다수 종목에서 반복되는 통계적 규칙과 포트폴리오 구성을 연구한다.

- 팩터, 횡단면 순위, 시계열 패턴, 시장 체제별 성과 연구
- 재현 가능한 Python 코드와 데이터 계보 보존
- 거래비용, 회전율, 용량, 포트폴리오 상호작용 평가
- 탐색, 분리 검증, sealed holdout, 미래 Shadow 순서 준수

Quant 결과는 Day와 Swing에 검증된 증거로 제공할 수 있지만 두 에이전트의 상황 판단을 대체하지 않는다.

## 4. 공통 서비스와 권한

| 서비스 | 책임 |
|---|---|
| Opportunity Scanner | 시장 변화와 연구 기회 탐지 |
| Market Context | 지수, 금리, 변동성, 업종 체제 정리 |
| News & Filing Search | 시각과 출처가 있는 뉴스·공시·실적 수집 |
| Evidence Registry | 모든 핵심 주장과 원천 증거 연결 |
| Experiment Sandbox | 생성된 Python 코드를 격리 실행 |
| Critic | 누수, 과적합, 반증 누락, 설명 불일치 검토 |
| Evaluation Kernel | replay, holdout, Shadow, Champion 비교 계산 |
| Risk Kernel | 최대 손실, 주문 수량, 거래 제한 결정 |
| Alpaca Paper Executor | Paper 주문, 체결, 취소, 청산, 재조정 |
| Dashboard Projector | 추천, 거래, 연구, Agent 버전 read model 생성 |

에이전트와 Loop Engineer는 인증 정보, 브로커 원시 호출, 위험 한도, 승격 기준을 직접 수정하거나 우회할 수 없다.

## 5. 지속 상태와 기억

각 에이전트는 공급자 모델 세션과 독립된 내구성 있는 상태를 유지한다.

### 5.1 ResearchTask

- 연구 목표와 질문
- 현재 가설과 반증 조건
- 확인한 증거와 출처
- 수행한 실험과 코드 버전
- 실패한 시도와 실패 원인
- 열린 의문과 다음 행동
- 재개 조건과 wake 시점
- 남은 호출·시간·실험 예산

### 5.2 Day Agent 기억

- `Session Memory`: 오늘의 테마, 대장주, 관심 종목, 현재 판단
- `Trade Memory`: 추천, 주문, 체결, 청산, 당시 근거
- `Research Memory`: 가설, 실험, 실패, 전략과 Agent 버전
- `Playbook Memory`: 미래 검증을 통과한 패턴과 적용 조건

다음 모델 호출은 이전 상태와 새로 변경된 증거를 읽고 연구를 이어간다. 매번 시장 전체를 처음부터 분석하지 않는다.

## 6. 가설 생성과 연구 루프

### 6.1 가설 생성 계기

- 비정상 거래량, 거래대금, 변동성 또는 스프레드 변화
- 뉴스, 공시, 실적, 정책, M&A 등 새로운 촉매
- 기존 전략의 반복 실패 또는 시장 체제별 성과 악화
- 예상 신호와 실제 체결·가격 반응의 불일치
- 기존 설명과 충돌하는 새로운 증거
- 마감 복기 또는 사용자가 등록한 연구 질문

### 6.2 가설 필수 요소

- 관찰과 데이터 기준 시각
- 경제적·행동적 메커니즘
- 검증 가능한 예측
- 적용 시장, 종목, 시간대, 시장 체제
- 진입, 손절, 목표, 청산, 무효화 조건
- 필요한 데이터와 단순 베이스라인
- 반증 조건과 예상 실패 체제
- 거래비용과 체결 가정

가설은 고정된 전략 열거형을 고르는 방식으로 제한하지 않는다. 에이전트는 가격·거래량·뉴스·공시·시장 체제를 조합해 새 가설과 일반 Python 실험 코드를 만들 수 있다.

### 6.3 다단계 도구 루프

하나의 ResearchTask 안에서 에이전트는 제한된 예산으로 다음 행동을 반복한다.

1. 현재 상태와 과거 실패를 읽는다.
2. 필요한 가격, 수급, 뉴스, 공시, 유사 사례를 조사한다.
3. 가설과 반증 조건을 작성한다.
4. Python 실험 코드 또는 Trade Thesis를 만든다.
5. 샌드박스 결과를 관찰하고 가설이나 코드를 수정한다.
6. 베이스라인과 비교하고 Critic 검토를 요청한다.
7. 증거가 충분하면 미래 Shadow 후보를 제출한다.
8. 부족하면 근거와 다음 행동을 남기고 다음 wake로 이월한다.

### 6.4 검증과 승격

`탐색 데이터 → 분리 검증 → sealed holdout → 등록 이후 미래 Shadow → Critic → 승격 게이트` 순서를 고정한다.

신규 연구는 같은 날 Paper 주문에 사용하지 않는다. 실시간 Paper 추천은 이미 승격된 Champion Agent와 Playbook만 사용한다.

## 7. Day Agent의 하루

### 7.1 장전

- 시장 체제와 밤사이 촉매 정리
- 상승률·거래대금·갭 후보를 테마로 묶기
- 촉매 신뢰도, 대장주 후보, 관찰 가격대, 무효화 조건 작성

### 7.2 장중

- 최신 완료 봉과 가용한 호가·체결·뉴스로 시장 지도 갱신
- 테마 강도와 대장주 교체 여부 평가
- Trade Thesis 생성 또는 `WATCH`, `NO TRADE`, `INSUFFICIENT EVIDENCE` 결정
- Risk Kernel을 통과한 추천만 Alpaca Paper Executor로 전달
- 추천 이후 `유지`, `진입 취소`, `논리 무효화`, `부분 청산`, `종료` 상태를 append-only로 기록

### 7.3 마감 후

손익만 보지 않고 시장 인식, 테마 선택, 촉매 해석, 대장주 판단, 수급 해석, 진입, 청산, 주문·체결 품질을 분리해 복기한다. 복기 결과는 새로운 ResearchTask 또는 Loop Engineering 문제로 등록한다.

## 8. Loop Engineering

### 8.1 세 개의 속도

- 장중 판단 루프: 승인된 Champion을 세션 동안 고정해 추천과 Paper 거래 수행
- 일일 학습 루프: 판단 단계별 성공·실패 진단과 연구 질문 생성
- 주간 또는 충분한 증거 도착 시 Loop Engineering: Challenger 생성, 검증, 승격 또는 폐기

### 8.2 수정 가능 범위

Loop Engineer는 테마 탐지, 증거 수집 순서, 대장주 평가, 수급 해석, 프롬프트, 도구 순서, 기억 검색, Playbook 선택, 실험 코드, 확신도 계산을 수정할 수 있다.

다음은 수정할 수 없다.

- Paper 전용 endpoint guard
- 계좌 및 종목별 위험 한도
- 주문 가능 시간과 장 마감 flat 규칙
- 데이터 최신성, 스프레드, 세션 검사
- 미래 데이터 누수 방지
- 감사 이력과 승격 기준

### 8.3 Champion–Challenger

Loop Engineer가 만든 Challenger는 replay, sealed holdout, 미래 Shadow에서 Champion과 병렬 비교한다. Shadow 단계에서는 추천만 만들며 Paper 주문을 제출하지 않는다.

평가 항목:

- 테마 탐지의 시기와 정확도
- 대장주 선정 품질
- 진입 후 최대 유리·불리 움직임
- 논리 무효화 감지 품질
- 확신도 보정
- 비용 반영 기대값과 시장 체제별 재현성
- 불필요한 추천과 `NO TRADE` 품질
- 설명과 실제 증거의 일치
- 주문 및 체결 차이

단기 손익 하나로 승격하지 않는다. 이상이 발생하면 직전 Champion으로 롤백할 수 있어야 한다.

### 8.4 학습의 의미

초기 학습은 모델 가중치 온라인 수정이 아니다.

1. 과거 사례를 검색하는 기억 학습
2. 체제별 유효 패턴을 갱신하는 Playbook 학습
3. 가설과 Python 전략을 진화시키는 전략 학습
4. 프롬프트, 도구, 정보 수집, 판단 순서를 개선하는 Agent 학습

충분한 고품질 판단·거래 데이터가 축적되기 전에는 파인튜닝하지 않는다.

## 9. 에이전트 간 협업

에이전트는 결론을 다수결로 합치지 않고 검증된 증거를 공유한다.

- Quant → Day: 현재 체제에서 유효한 통계 패턴
- Swing → Day: 지속 가능한 테마와 핵심 기업
- Day → Swing: 실제 장중 자금 이동과 테마 약화 징후
- Day → Quant: 반복적으로 관찰됐지만 아직 정량화되지 않은 패턴
- Quant → Swing: 중기 팩터와 체제 변화

각 에이전트는 자체 근거와 추천 책임을 유지한다. Day, Swing, Quant마다 별도 Loop Engineer를 두고 Evaluation Kernel만 공유한다.

## 10. 모델 라우팅

- 경량 모델: 뉴스·공시 분류, 중복 제거, 단순 추출과 요약
- 강한 추론 모델: 테마, 수급, 대장주, Trade Thesis 판단
- 강한 추론·코딩 모델: 연구 가설, Python 코드, Loop Engineering
- Critic 모델: 반증, 누수, 과적합, 설명 불일치 검토

핵심 가설과 거래 판단은 비용 절감을 이유로 경량 모델에 자동 하향하지 않는다. 지속성은 모델 공급자의 세션이 아니라 프로젝트의 ResearchTask와 기억 저장소가 담당한다.

모든 핵심 자연어 주장은 시간과 출처가 있는 증거에 연결한다. 증거가 없거나 오래됐으면 추천 대신 `INSUFFICIENT EVIDENCE` 또는 `NO TRADE`를 기록한다.

## 11. 추천과 대시보드

### 11.1 추천 카드

- 종목, 방향, 추천 시각, 데이터 기준 시각
- 테마, 촉매, 대장주 선정 근거, 수급 판단
- 진입가 또는 조건, 손절가, 목표가, 손익비
- 무효화 조건, 확신도, Playbook, Agent 버전
- 관찰, 진입 대기, 주문, 체결, 부분 청산, 종료, 취소 상태

추천 변경은 최초 판단을 덮어쓰지 않고 immutable history로 추가한다. 추천, 주문, 체결, 청산은 동일한 recommendation ID 계보로 연결한다.

### 11.2 첫 화면

1. 현재 주도 테마와 시장 체제
2. 대장주와 관심 종목
3. 활성 추천의 진입·손절·목표
4. Alpaca Paper 주문, 포지션, 평가 결과
5. 종료된 거래와 판단 복기
6. Champion과 Shadow Challenger
7. Loop Engineer의 최근 문제 진단과 개선 내용

연구 화면은 가설, 증거, 코드·Agent 버전, replay·holdout·Shadow 결과, 승격·폐기·롤백 이유, 다음 연구 행동을 표시한다.

## 12. 실패 안전 동작

- 데이터가 현재 세션의 최신 완료 봉이 아니면 신규 추천과 주문을 차단한다.
- 스프레드 또는 필수 증거가 누락되면 신규 진입을 차단한다.
- 뉴스 시각이나 출처가 불명확하면 촉매 근거로 사용하지 않는다.
- 모델 호출이 실패하면 현재 Champion 상태를 보존하고 새 주문을 만들지 않는다.
- 주문 상태가 불일치하면 신규 진입을 중단하고 Paper 브로커 상태를 재조정한다.
- Challenger나 Loop Engineer가 실패해도 운영 Champion에는 영향을 주지 않는다.
- 같은 봉에서 stop과 target이 충돌하면 stop으로 처리한다.
- 장 마감에 Day 포지션을 청산하고 Paper 계좌 상태와 내부 상태를 재조정한다.
- 모든 실패한 추천, 전이, 실험, 승격 결정은 감사 DB에 보존한다.

## 13. 구현 순서와 완료 기준

### 13.1 1차 범위

US Day Agent 하나의 자연 시장 수직 경로를 완성한다.

1. 실시간 데이터와 뉴스로 테마·대장주 탐지
2. 근거가 연결된 Trade Thesis와 추천 카드 생성
3. 진입가·손절가·목표가를 대시보드와 알림에 표시
4. Risk Kernel 통과 후 Alpaca Paper 자동 주문
5. 체결, 부분 체결, 취소, 손절, 익절, 장 마감 청산 반영
6. 추천부터 최종 결과까지 동일 계보로 추적
7. 마감 복기와 신규 ResearchTask 생성
8. Loop Engineer가 Challenger 생성
9. 다음 자연 세션에서 Champion과 Shadow 병렬 비교
10. 개선, 폐기, 롤백 이유를 대시보드에 표시
11. 재시작 후 추천·주문·연구 상태의 유실과 중복이 없음

### 13.2 동결 범위

US Day 수직 경로가 통과할 때까지 새 제품 에이전트, 파생 실행, 실거래 주문, 복잡한 토론형 swarm, 모델 파인튜닝, 필요성이 검증되지 않은 상태 모델을 추가하지 않는다.

다음 확장 순서는 Swing Agent, Quant Agent, 한국 Day Shadow다.

### 13.3 제품 주장

Paper 결과는 실제 가상 주문과 판단 검증 결과로 표시한다. Paper, replay, synthetic, backtest 결과로 실거래 수익성을 주장하지 않는다.
