# 로컬 컴퓨터 기반 자율 트레이딩 에이전트 설계

**상태:** 사용자 승인

**제품 목표:** 24시간 켜진 로컬 Mac에서 지속형 자율 에이전트가 한국·미국 시장을 관찰하고, 테마·수급·뉴스·공시를 조사하고, 가설과 진입·손절·목표가를 만들고, 모의매매와 포지션 관리를 수행하고, 결과를 학습해 전략과 자신의 코드를 개선한다. 사용자는 이 전 과정을 대시보드와 알림으로 실시간 확인한다.

## 1. 설계 결정

이 설계는 다음 결정을 고정한다.

- 현재 중앙 6개 패밀리의 `증거 수신 → LLM 1회 호출 → 종료` 방식을 폐기한다.
- 하나의 지속형 `Autonomous Trading Supervisor`가 장기 목표와 미완료 작업을 소유한다.
- 에이전트는 목표가 해결될 때까지 여러 번 도구를 사용하고, 관찰 결과에 따라 계획을 수정하고, 다음 행동을 스스로 예약한다.
- 운영 본체는 24시간 켜진 로컬 Mac이다. 별도 클라우드 서버를 필수로 사용하지 않는다.
- 로컬 Mac은 에이전트 전용 macOS 사용자, 브라우저 프로필, 터미널, 파일시스템, Computer Use 환경을 제공한다.
- 시장데이터 어댑터, Alpaca Paper 실행기, 감사 원장, 대시보드 투영기는 검증된 연결부로 재사용한다.
- 기존 one-shot 연구 런타임, 단절되는 wake 정책, 원본 증거를 잃는 재시도 구조는 재사용하지 않는다.
- Loop Engineer는 성과 저하, 반복 실패, 새 연구 능력 필요가 확인됐을 때 핵심 코드까지 수정할 수 있다.
- 검증을 통과한 코드 변경은 사용자 승인 없이 모의운영 버전으로 자동 승격할 수 있다.
- 실제 자금 거래 경로는 존재하지 않는다. 미국 주문은 정확히 Alpaca Paper만 허용하고 한국 시장과 다른 공급자는 읽기 또는 내부 가상체결만 허용한다.
- 수익률이 아니라 지속성, 근거 품질, 재현성, 미래정보 차단, 모의운영 결과를 완료 기준으로 사용한다.

## 2. 기존 설계와의 관계

이 설계는 `2026-08-21-specialist-trading-agents-loop-engineering-design.md`의 지속형 ResearchTask와 Loop Engineering 방향을 승계하되 중앙 런타임을 새로 정의한다.

다음 구성은 폐기 대상이다.

- 모델 호출 1회로 끝나는 연구 사이클
- 도구가 비활성화된 LLM 결정기
- 세션과 실제 장기기억이 없는 `memory_namespace`
- 새 증거나 열린 작업이 없으면 영구 정지하는 actor wake 정책
- 재시도 시 원본 권위 증거 대신 retry envelope만 전달하는 방식
- 서로 연결되지 않은 primary family, strategy research, KR Day, US Day 런타임

다음 구성은 재사용 대상이다.

- KIS, LS, Alpaca 등 검증된 시장데이터 읽기 어댑터
- 정확한 `https://paper-api.alpaca.markets`만 허용하는 Alpaca Paper 연결부
- 추천·주문·체결·포지션·성과의 append-only 감사 기록
- 현재 데이터 적격성 검사와 미래정보 누출 방지 로직
- 대시보드 read model과 사용자 알림 채널
- 기존 연구·추천·모의체결 데이터 중 출처와 시각이 검증되는 기록

기존 서비스는 새 Supervisor가 운영 수직 경로를 증명할 때까지 비교·복귀용으로 유지한다. 전환이 완료되면 legacy actor의 자동 실행을 중지하고 읽기 전용 이력으로 남긴다.

## 3. Local Agent Computer

로컬 Mac은 Grok Bot의 persistent cloud computer에 대응하는 `Local Agent Computer` 역할을 한다.

### 3.1 운영 조건

- Mac 절전과 자동 로그아웃을 비활성화한다.
- 재부팅 후 Supervisor, 대시보드, 알림, 필수 데이터 서비스가 자동 시작된다.
- 에이전트 전용 macOS 사용자와 전용 브라우저 프로필을 사용한다.
- GUI 세션이 없어도 가능한 시장데이터, 연구, 주문, 복기 작업은 백그라운드에서 계속 실행한다.
- Computer Use가 필요한 작업은 GUI 세션과 브라우저 상태를 먼저 확인한다.
- 인터넷 단절, 브라우저 종료, LLM 인증 만료, 프로세스 충돌을 감지하고 복구 작업을 예약한다.
- 소스 코드 수정은 실행 중인 작업 디렉터리가 아닌 별도 Git worktree에서 수행한다.

### 3.2 도구 선택 원칙

| 작업 | 우선 도구 | 대체 도구 |
|---|---|---|
| 실시간 시장데이터 | 공식 읽기 API·WebSocket | 검증된 저장 데이터 |
| 미국 모의주문 | Alpaca Paper API | 없음 |
| 한국 모의체결 | 내부 가상체결 원장 | 없음 |
| 뉴스·공시·리서치 | 검색·공식 문서·읽기 API | 브라우저 Computer Use |
| 로그인 웹사이트 조사 | 전용 브라우저 | Computer Use |
| 코드 수정·검증 | 터미널·Git worktree | 없음 |
| 사용자 보고 | 대시보드·Hermes/Telegram | 로컬 감사 로그 |

Computer Use는 API가 없는 화면과 사람의 브라우저 행동이 필요한 조사에 사용한다. 가격 수집과 주문처럼 정확성·재시도가 중요한 경로는 브라우저 클릭보다 검증된 API를 우선한다.

## 4. 에이전트 구성

### 4.1 Autonomous Trading Supervisor

Supervisor는 다음 장기 목표를 소유한다.

> 한국·미국 시장에서 유효한 기회를 관찰하고, 모의매매로 검증하며, 실패에서 학습해 연구·매매 능력을 지속적으로 개선한다.

Supervisor의 책임은 다음과 같다.

- 모든 ResearchTask의 생성, 우선순위, 소유권, 상태, 다음 wake 관리
- 현재 시장 세션과 미완료 포지션을 기준으로 작업 재개
- 전문 에이전트에게 조사와 판단 위임
- 서로 충돌하는 결론의 조정과 Critic 호출
- 모의주문 및 포지션 관리 작업의 연속성 보장
- 반복 실패와 성과 저하를 Loop Engineer 작업으로 승격
- 비용, 처리량, 장애 상태를 보고하되 열린 목표를 조용히 종료하지 않음

### 4.2 Market Observer

- 한국·미국 시장 세션, 지수, 업종, 변동성, 거래대금 지도를 유지한다.
- 테마 동시성, 상대 거래량, 체결 강도, 스프레드, 갭, VWAP 반응을 관찰한다.
- 뉴스, 공시, 실적, 경제 이벤트의 출처와 최초 시각을 증거로 등록한다.
- 의미 있는 변화가 있을 때 Opportunity Agent를 깨운다.

### 4.3 Opportunity Agent

- 종목, 테마, 이벤트, 비정상 수급 후보를 탐색한다.
- 단순 가격 상승과 근거 있는 기회를 구분한다.
- 추가 조사 항목과 다음 관찰 조건을 기록한다.
- 기각한 후보도 이유와 결과를 보존해 반복 탐색을 줄인다.

### 4.4 Trading Agent

- 사람처럼 시장 맥락, 테마 단계, 대장주, 거래대금과 관측 가능한 수급을 함께 해석한다.
- 추천마다 시각, 진입가, 손절가, 목표가, 무효화 조건, 포지션 크기, 근거를 생성한다.
- 미국은 Alpaca Paper 주문 후보를 만들고 실행 결과를 추적한다.
- 한국은 내부 가상체결 원장에서 모의 진입과 청산을 추적한다.
- 근거가 부족하면 `no-trade`를 선택하되 다음 관찰 조건과 시각을 반드시 남긴다.

### 4.5 Position Manager

- 미체결 주문과 보유 모의 포지션을 시장 세션 동안 지속 추적한다.
- 손절, 목표, 시간 종료, 테마 약화, 대장주 교체, 새로운 공시에 반응한다.
- 장중 판단과 실제 모의체결의 차이를 기록한다.
- 미국 Day 포지션은 정해진 당일 청산 정책에 따라 Alpaca Paper에서 정리한다.

### 4.6 Research Agent

- 거래 결과와 시장 관찰에서 검증 가능한 가설을 만든다.
- 논문, 공식 데이터, 과거 데이터, 미래 Shadow를 사용해 가설을 검증한다.
- 가설별 지지 증거, 반증, 적용 시장 체제, 실패 조건을 유지한다.
- Day, Swing, Systematic 연구를 독립된 시간축과 평가 기준으로 관리한다.

### 4.7 Critic Agent

- 확증편향, 미래정보 누출, 과적합, 거래비용 누락, 설명과 행동의 불일치를 검사한다.
- 성공 거래도 반대 가설과 우연 가능성을 검토한다.
- 반복 오류가 전략 문제인지 런타임·도구·데이터 문제인지 분류한다.
- 구조적 결함일 때 Loop Engineer 호출 근거를 제출한다.

### 4.8 Loop Engineer

- 허용된 트리거가 발생했을 때 프롬프트, 전략, 도구, 데이터 처리, 기억 구조, 핵심 런타임 코드를 수정한다.
- 별도 worktree에서 수정하고 테스트, replay, shadow 결과를 변경 제안과 함께 보존한다.
- 기존 champion과 후보 challenger를 비교한다.
- 승격 후 이상이 발견되면 직전 정상 버전으로 자동 복귀한다.

## 5. 지속형 ResearchTask

모든 에이전트 행동은 durable `ResearchTask`에 속한다. Task는 LLM 응답 한 번이 끝났다고 완료되지 않는다.

필수 상태는 다음과 같다.

```text
task_id
goal
owner_agent
market_scope
status
priority
source_evidence_ids
working_memory_ids
current_plan
completed_actions
pending_actions
next_wake_at
next_wake_event
blocked_reason
retry_lineage
agent_version
created_at
updated_at
terminal_reason
```

상태 전이는 다음과 같다.

```text
queued
→ observing
→ researching
→ deliberating
→ acting | waiting_event | waiting_time | blocked
→ evaluating
→ learning
→ observing | completed | abandoned
```

`no-trade`, `no-action`, 데이터 부재, LLM 실패는 자동으로 `completed`를 의미하지 않는다. 다음 관찰 조건이 있으면 `waiting_event` 또는 `waiting_time`으로 전환한다. 실제로 목표가 해소됐거나 명시적으로 폐기된 경우에만 terminal 상태가 된다.

재시도는 원본 `source_evidence_ids`, 현재 계획, 마지막 성공 action, 오류 정보를 모두 계승한다. retry envelope 자체를 원본 시장 증거처럼 해석하지 않는다.

## 6. 다단계 에이전트 루프

한 사이클의 기본 흐름은 다음과 같다.

```text
현재 상태와 기억 복원
→ 시장·포지션·작업 변화 관찰
→ 현재 목표에 필요한 다음 행동 선택
→ 도구 호출
→ 관찰 결과 저장
→ 계획 수정 또는 추가 도구 호출
→ 추천·모의주문·관망·연구 결과 제출
→ Critic 검토
→ 결과 추적 작업 생성
→ 다음 wake 예약
```

모델 호출 횟수를 1로 고정하지 않는다. Task별 시간, 토큰, 도구 호출 예산을 갖되 예산 소진 시 작업을 잃지 않고 다음 wake로 이어간다. Supervisor는 작업 중요도, 시장 시간, 열린 포지션에 따라 예산을 재배분한다.

## 7. 기억 구조

### 7.1 작업 기억

현재 가설, 조사 계획, 도구 관찰, 미완료 action, 실패 지점과 다음 단계를 보존한다. ResearchTask 재개 시 가장 먼저 복원한다.

### 7.2 시장 기억

종목, 테마, 촉매, 대장주, 거래대금, 가격 반응, 관측 가능한 수급이 시간에 따라 어떻게 변했는지 저장한다. 사실, 추론, 미확인 주장을 구분한다.

### 7.3 전략 기억

전략 버전, 적용 조건, 거래 결과, 실패 패턴, 체제별 성과, 반증을 연결한다. 단일 성공이나 누적 수익만으로 전략을 승격하지 않는다.

### 7.4 자기개선 기억

코드 변경의 문제 증거, 가설, diff, 검증 결과, 승격·복귀 이력, 당시 운영 버전을 연결한다. 동일 실패가 재발하면 과거 수정과 결과를 검색한다.

기억은 프롬프트에 붙이는 문자열이 아니라 조회·쓰기·버전·출처가 있는 저장소다. 변경 가능한 요약과 불변 원본 증거를 분리한다.

## 8. 시장별 운영 리듬

### 8.1 한국 시장

- 장전에는 공시, 뉴스, 예상 테마, 전일·해외 시장 연결을 조사한다.
- 장중에는 테마 확산, 거래대금, 체결, 대장주 교체, 가격 구조를 짧은 간격으로 관찰한다.
- 추천과 진입은 현재 한국 세션의 최신 완료 bar와 현재 증거만 사용한다.
- 주문 공급자는 사용하지 않고 내부 가상체결 원장으로 진입, 손절, 목표, 청산을 추적한다.
- 장 종료 후 추천과 가상체결을 복기하고 다음 세션 연구 과제를 만든다.

### 8.2 미국 시장

- 장전에는 지수, 섹터, 실적, 경제 일정, 뉴스, 갭과 유동성을 조사한다.
- 신규 장중 추천은 현재 뉴욕 세션의 최신 완료 bar만 사용한다. 과거 bar는 지표 준비에만 사용하고 과거 시점 추천을 만들지 않는다.
- 장중에는 현재 세션 데이터로 추천과 Alpaca Paper 주문을 관리한다.
- 주문, 취소, 포지션 읽기, 당일 청산은 paper endpoint guard를 통과한 경우에만 수행한다.
- 같은 bar에서 손절과 목표가가 모두 충족된 것으로 보이면 손절을 먼저 적용한다.
- 장 종료 후 Paper 체결과 추천 의도를 대조하고 슬리피지·미체결·포지션 관리 오류를 평가한다.

### 8.3 휴장 시간

- 논문과 공식 자료 조사
- 가설 생성과 반증
- replay와 holdout 평가
- 장중 결과 복기
- Loop Engineer 후보 수정과 shadow 준비
- 다음 한국장·미국장 작업 계획 생성

## 9. 자기수정 트리거

Loop Engineer는 다음 중 하나가 증거로 충족될 때 호출된다.

- 같은 원인의 실패가 3회 이상 반복된다.
- 충분한 미래 표본에서 전략 성과가 champion 또는 사전 기준보다 지속적으로 악화된다.
- 동일한 손절·오판 패턴이 여러 독립 거래에서 반복된다.
- 데이터 소스, 웹사이트, 공급자 계약 또는 입력 스키마가 변경됐다.
- 현재 도구로 중요한 가설을 검증할 수 없다.
- Critic이 전략 파라미터가 아닌 구조적 런타임 결함으로 판정한다.

단일 손실, 단일 예외, LLM의 근거 없는 자기평가만으로 코드를 수정하지 않는다. 트리거는 감사 가능한 evidence bundle을 가져야 한다.

## 10. 코드 변경, 검증, 승격과 복귀

자기수정 파이프라인은 다음 순서를 고정한다.

```text
문제 evidence bundle
→ 원인 가설
→ 격리 Git worktree 생성
→ 코드·프롬프트·도구 수정
→ 정적 검사와 표적 테스트
→ 과거 시장 replay
→ 미래정보·데이터 계보 검사
→ champion 대비 challenger 평가
→ 한국·미국 Paper Shadow
→ 자동 승격
→ 운영 감시
→ 유지 또는 자동 복귀
```

승격 평가는 다음을 포함한다.

- 거래비용 반영 손익과 최대 낙폭
- 손절과 포지션 관리 준수율
- 추천 필수 필드와 근거 완전성
- 미래정보 누출과 데이터 날짜 오류
- 과도한 거래와 중복 포지션
- 여러 시장 체제에서의 안정성
- 오류 후 ResearchTask와 포지션 복구
- 기존 결함이 재현되지 않는다는 증거
- 새 회귀가 없다는 표적·전체 검증

승격은 모의운영 환경에만 적용한다. 실행 중인 champion을 직접 편집하지 않고 불변 release artifact를 교체한다. 새 버전에서 오류율, 데이터 적격성 실패, 주문 불일치, ResearchTask 유실이 임계치를 넘으면 직전 정상 release로 자동 복귀하고 해당 후보를 실패 이력으로 보존한다.

## 11. 실패 처리

### 11.1 LLM 실패

- 원본 목표와 증거를 보존한다.
- 동일 요청의 무한 반복 대신 오류 유형에 따라 재인증, 모델 대체, 프롬프트 축소, 다음 wake를 선택한다.
- 대체 모델 사용 여부와 결과 차이를 감사 기록에 남긴다.
- 복구 불가능하면 `blocked`와 정확한 이유, 다음 확인 시각을 기록한다.

### 11.2 데이터 실패

- 오래된 데이터로 현재 추천을 생성하지 않는다.
- 공급자별 상태와 마지막 정상 시각을 기록한다.
- 대체 데이터는 출처와 품질 차이를 표시한다.
- 데이터 복구 이벤트에 Task를 다시 깨운다.

### 11.3 브라우저와 Computer Use 실패

- 로그인, CAPTCHA, 화면 구조 변경, GUI 세션 부재를 구분한다.
- 읽기 API나 검색 도구로 대체할 수 있으면 자동 전환한다.
- 사람의 인증이 필요한 경우에만 사용자에게 정확한 한 단계 작업을 요청한다.
- 화면 구조 변경이 반복되면 Loop Engineer 도구 수리 작업을 만든다.

### 11.4 프로세스와 Mac 장애

- Supervisor heartbeat와 durable Task DB를 분리한다.
- 프로세스 재시작 후 열린 Task, 주문, 포지션, 예정 wake를 재조정한다.
- Mac 재부팅 후 서비스 시작 순서와 readiness를 검사한다.
- 알림 채널 실패가 트레이딩·연구 루프를 중단시키지 않는다.

## 12. 대시보드와 사용자 경험

대시보드는 다음을 실시간으로 보여준다.

- 각 에이전트의 현재 목표, 단계, 사용 중인 도구와 마지막 행동
- 한국·미국 시장 상태와 다음 wake
- 관찰종목, 테마, 촉매, 거래대금과 수급 해석
- 가설, 지지 증거, 반대 증거, Critic 판정
- 추천 시각, 진입가, 손절가, 목표가, 무효화 조건, 포지션 크기와 근거
- 모의주문, 체결, 포지션, 실현·미실현 결과
- 실패 Task, 재시도 계보, 차단 이유와 복구 예정 시각
- 장 종료 복기와 새로 학습한 내용
- champion·challenger 버전, 코드 변경 이유, 검증, 승격·복귀 이력
- LLM과 도구 사용량, 일일·월간 예상 비용

사용자는 대시보드에서 에이전트를 중지, 재개, 우선순위 변경할 수 있다. 그러나 정상 운영 중 매 행동을 승인할 필요는 없다.

## 13. 실행 경계와 비밀정보

자율성은 넓게 허용하되 실제 자금 거래 금지는 에이전트가 수정할 수 없는 host policy로 둔다.

- Alpaca 거래 base URL은 정확히 `https://paper-api.alpaca.markets`만 허용한다.
- 그 외 Alpaca 거래 URL은 HTTP 요청 전에 거부한다.
- KIS와 다른 공급자는 주문, 잔고 변경, 계좌 변경을 호출하지 않는다.
- LS는 검토된 시장데이터·뉴스 계약만 사용하고 계좌·주문 계약을 호출하지 않는다.
- 한국 거래는 내부 가상체결 원장만 사용한다.
- 비밀키, 토큰, 계좌 식별자는 채팅, 로그, 기억, 코드 diff, 대시보드에 노출하지 않는다.
- 추천은 시각, 진입, 손절, 목표, 근거와 불변 결과 이력을 갖는다.
- synthetic, replay, backtest, paper 결과를 실제 수익성으로 주장하지 않는다.

Loop Engineer는 이 host policy를 포함하는 보호 경계 밖의 코드를 수정할 수 없다. 경계 변경 시도는 실패 후보로 기록하고 승격하지 않는다.

## 14. 비용과 사용량

로컬 Mac을 운영 본체로 사용하므로 별도 클라우드 컴퓨팅 비용은 필수가 아니다. 비용은 LLM, 선택적 유료 시장데이터, 저장소 백업에서 발생한다.

- 결정론적 scanner가 전체 시장을 먼저 줄이고 LLM은 의미 있는 후보와 열린 Task에 집중한다.
- Task별 토큰·시간·도구 예산과 일일·월간 사용량 목표를 둔다.
- 비용 목표 초과 시 신규 저우선 연구를 늦추되 열린 포지션 관리와 감사 기록은 계속한다.
- 비용 절약을 이유로 열린 목표를 terminal 처리하지 않는다.
- 유료 미국 전체 거래소 데이터는 무료 데이터로 자율 루프를 검증한 뒤 별도 운영 결정으로 추가한다.

## 15. 전환 전략

### 단계 1: 기반 교체

- durable ResearchTask 저장소와 Autonomous Trading Supervisor를 구축한다.
- 실제 기억 조회·쓰기, 도구 호출, multi-step continuation을 연결한다.
- legacy retry envelope 대신 원본 evidence lineage를 보존한다.

### 단계 2: 한국 시장 자연 수직 경로

- Market Observer부터 Opportunity, Trading, Position, Research, Critic까지 한 세션에서 연결한다.
- 한국 가상체결과 장중 재관찰, 장 종료 복기를 증명한다.

### 단계 3: 미국 Alpaca Paper 수직 경로

- 기존 US Day의 유효한 Paper 연결부를 새 Supervisor에 연결한다.
- 주문·체결·포지션·당일 청산과 재시작 reconciliation을 증명한다.

### 단계 4: Loop Engineer

- 반복 실패 evidence bundle, 격리 worktree, 자동 검증, challenger shadow, 승격·복귀를 연결한다.
- 실제 결함 하나를 end-to-end로 탐지하고 수정하는 운영 검증을 수행한다.

### 단계 5: legacy 종료

- 새 런타임과 기존 런타임의 중복 추천·주문 가능성을 제거한다.
- legacy actor 자동 실행을 중지한다.
- 기존 DB와 상태는 감사 및 복귀 참고용 읽기 전용 이력으로 유지한다.

## 16. 완료 판정 기준

### 16.1 지속성

- Mac 재부팅 후 자동 시작한다.
- Codex 앱과 대화창을 닫아도 계속 작동한다.
- 프로세스 장애 후 목표, 원본 증거, 미완료 action과 다음 wake를 복원한다.
- 모든 비종료 Task는 다음 시각 또는 다음 이벤트를 가진다.

### 16.2 자율 연구 루프

실제 관찰 가능한 한 Task에서 다음 흐름을 증명한다.

```text
시장 관찰
→ 종목·테마 포착
→ 추가 자료 자율 조사
→ 가설 생성
→ Critic 검토
→ 진입 또는 관망
→ 결과 추적
→ 회고
→ 다음 행동 예약
```

LLM 한 번 호출 후 종료되는 구현은 통과하지 못한다.

### 16.3 한국·미국 장중 모의운영

- 현재 시장 세션의 적격 데이터만 사용한다.
- 관찰종목 포착 이유와 다음 조건을 표시한다.
- 추천에 진입, 손절, 목표, 크기와 근거가 있다.
- 미국은 Alpaca Paper, 한국은 내부 가상체결을 사용한다.
- 열린 포지션을 장중 지속 관리한다.
- 관망도 후속 wake와 결과 평가를 가진다.

### 16.4 자기개선

기존 반복 결함 또는 격리된 재현 결함을 사용해 다음을 증명한다.

```text
Critic의 반복 실패 감지
→ Loop Engineer 작업
→ 코드 수정
→ 테스트와 시장 replay
→ Paper Shadow
→ 자동 승격
→ 이상 시 자동 복귀
```

### 16.5 사용자 표면

- 대시보드에서 에이전트의 현재 작업과 다음 행동을 실시간 확인한다.
- 연구, 추천, 주문, 포지션, 결과, 학습, 코드 버전을 하나의 계보로 탐색할 수 있다.
- 알림에는 단순 종목명이 아니라 행동, 근거, 가격 수준, 다음 확인 시각이 포함된다.

### 16.6 연속 운영

- 24시간 무중단 기술 검증을 통과한다.
- 한국장과 미국장 각각 자연 장중 시나리오를 통과한다.
- 최소 5개 거래일 연속 Forward Shadow를 완료한다.
- 사용자 메시지가 없어도 연구와 모의운영이 이어진다.
- 모든 실거래 엔드포인트가 네트워크 요청 전에 거부되는 것을 증명한다.

## 17. 비목표

- 실제 자금 거래
- 실거래 계좌 연결 또는 실거래 주문 준비
- 검증되지 않은 수익 보장
- 모든 웹사이트를 Computer Use로만 조작하는 구조
- 단일 성공 거래를 근거로 한 전략 또는 코드 자동 승격
- 에이전트별 완전한 보안 격리로 오해할 수 있는 공유 브라우저·파일 구조

## 18. 설계 완료 조건

이 문서는 다음 구현 결정을 미정으로 남기지 않는다.

- 운영 본체: 24시간 켜진 로컬 Mac
- 자율성 단위: durable ResearchTask와 multi-step tool loop
- 코드 수정 권한: Loop Engineer의 조건부 핵심 코드 수정
- 배포 권한: 검증 통과 후 모의운영 자동 승격과 자동 복귀
- 주문 경계: 미국 Alpaca Paper와 한국 내부 가상체결만 허용
- 전환 방식: 중앙 자율 런타임 신규 구축 후 legacy actor 종료
- 완료 기준: 실제 자연 시장 수직 경로, 자기개선, 24시간 및 5거래일 Forward Shadow
